# Service Desk

Backend-сервис для регистрации и обработки заявок о технических неисправностях в университете. Студент создаёт заявку, система назначает доступного специалиста, а специалист проводит её через рабочий процесс до завершения или блокировки.

Проект создан как практическая работа по Java Backend: в нём реализованы REST API, бизнес-правила, хранение данных в PostgreSQL, транзакции, аудит, аутентификация и автоматические тесты.

## Возможности

- регистрация аккаунтов студентов;
- хранение паролей в виде BCrypt-хешей;
- аутентификация через серверную HTTP-сессию;
- получение данных текущего пользователя и безопасный logout;
- создание и просмотр заявок;
- ручное и автоматическое назначение специалистов;
- выбор специалиста с учётом доступности, местоположения, уровня и приоритета заявки;
- начало, завершение и блокировка работы с указанием причины;
- освобождение специалиста после завершения или блокировки заявки;
- аудит создания заявки в той же транзакции;
- управление сменами специалистов;
- валидация входных DTO и проверка переходов между статусами.

## Основные бизнес-процессы

Жизненный цикл заявки:

```text
CREATED -> ASSIGNED -> IN_PROGRESS -> COMPLETED
                              |
                              -> BLOCKED -> ASSIGNED
```

Состояния специалиста:

```text
OFF_DUTY -> AVAILABLE -> BUSY -> AVAILABLE -> OFF_DUTY
```

При автоматическом назначении рассматриваются только специалисты со статусом `AVAILABLE`. Сначала система предпочитает специалиста в том же местоположении, затем учитывает соответствие уровня специалиста приоритету заявки.

## Структура проекта

```text
src/main/java/com/example/service_desk/
├── account/       аккаунты, регистрация и DTO
├── assignment/    назначение и завершение работы
├── audit/         события аудита заявок
├── security/      Spring Security и загрузка пользователей из БД
├── specialist/    специалисты и управление сменами
└── ticket/        заявки, REST API и работа с хранилищем
```

Слои приложения разделены по ответственности:

```text
HTTP request -> Controller -> Service -> Repository -> PostgreSQL
```

Контроллеры принимают и возвращают DTO, сервисы содержат бизнес-логику и границы транзакций, а репозитории отвечают за доступ к данным.

## Запуск

### Требования

- JDK 25;
- PostgreSQL;
- пользователь PostgreSQL с правом создавать и изменять таблицы.

Отдельно устанавливать Maven не нужно: в репозитории находится Maven Wrapper.

### 1. Создать базы данных

```bash
createdb service_desk
createdb service_desk_test
```

### 2. Настроить подключение

По умолчанию приложение подключается к `localhost:5432/service_desk` под именем текущего системного пользователя. При необходимости задайте параметры через переменные окружения:

```bash
export SERVICE_DESK_DB_URL=jdbc:postgresql://localhost:5432/service_desk
export SERVICE_DESK_DB_USERNAME=postgres
export SERVICE_DESK_DB_PASSWORD=your_password
```

Для интеграционных тестов используются отдельные переменные:

```bash
export SERVICE_DESK_TEST_DB_URL=jdbc:postgresql://localhost:5432/service_desk_test
export SERVICE_DESK_TEST_DB_USERNAME=postgres
export SERVICE_DESK_TEST_DB_PASSWORD=your_password
```

### 3. Запустить приложение

```bash
./mvnw spring-boot:run
```

Flyway автоматически применит миграции из `src/main/resources/db/migration`. Hibernate работает в режиме `validate` и проверяет соответствие сущностей созданной схеме.

## API

| Метод | URL | Назначение | Текущий доступ |
|---|---|---|---|
| `POST` | `/api/auth/register` | Зарегистрировать студента | публичный |
| `POST` | `/login` | Выполнить вход и создать сессию | публичный |
| `GET` | `/api/auth/me` | Получить текущий аккаунт | аутентифицированный пользователь |
| `POST` | `/api/auth/logout` | Завершить сессию, ответ `204` | аутентифицированный пользователь |
| `POST` | `/api/tickets` | Создать заявку от текущего аккаунта | `STUDENT` |
| `GET` | `/api/tickets` | Получить список заявок | аутентифицированный пользователь |
| `GET` | `/api/tickets/{ticketId}` | Получить заявку | аутентифицированный пользователь |
| `PATCH` | `/api/tickets/{ticketId}/start` | Начать работу | аутентифицированный пользователь |
| `PATCH` | `/api/tickets/{ticketId}/automatic-assignment` | Назначить специалиста автоматически | аутентифицированный пользователь |
| `PATCH` | `/api/tickets/{ticketId}/assignment` | Назначить специалиста вручную | аутентифицированный пользователь |
| `PATCH` | `/api/tickets/{ticketId}/complete` | Завершить заявку | аутентифицированный пользователь |
| `PATCH` | `/api/tickets/{ticketId}/block` | Заблокировать заявку с причиной | аутентифицированный пользователь |
| `POST` | `/api/specialists` | Зарегистрировать специалиста | `ADMIN` |
| `GET` | `/api/specialists` | Получить список специалистов | аутентифицированный пользователь |
| `GET` | `/api/specialists/{specialistId}` | Получить специалиста | аутентифицированный пользователь |
| `PATCH` | `/api/specialists/{specialistId}/shift/start` | Начать смену | аутентифицированный пользователь |
| `PATCH` | `/api/specialists/{specialistId}/shift/finish` | Завершить смену | аутентифицированный пользователь |

Изменяющие запросы защищены CSRF. Неаутентифицированный запрос к защищённому API получает `401 Unauthorized`, а пользователь без требуемой роли — `403 Forbidden`.

## Тестирование

Для запуска всего набора тестов:

```bash
./mvnw test
```

В проекте используются:

- unit-тесты бизнес-сущностей и выбора специалиста;
- тесты сервисов и репозиториев;
- MockMvc-тесты REST-контроллеров;
- интеграционные тесты JPA/PostgreSQL;
- тесты транзакционного rollback;
- тесты регистрации, BCrypt, входа, сессии, logout, CSRF и ролей.

Тесты работают с отдельной базой `service_desk_test` и выполняются транзакционно, поэтому не изменяют рабочие данные.
